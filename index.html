01 / DATASET

Scope & evaluated models

This dashboard displays available verification statistics for seven global guidance systems: GFS, AIGFS, CFS, CMC, ECMWF, FNMOC, and UKMET. The available model group is Global. The available geographic domains are Global, Northern Hemisphere, Southern Hemisphere, Tropics, and CONUS. Upper-air and mean sea-level pressure scores are available in the global domains, while the current 2-m temperature, 10-m wind, and 24-hour precipitation products use the CONUS domain.

The archive supports up to 90 daily valid dates and Day 0 through Day 15. Only available daily scores are displayed. Available metrics include height, temperature, pressure, 10-m wind, and 24-hour precipitation scores. When a metric is available only in another region, selecting it switches to that region across the dashboard pages. The Home scorecard includes its fixed set of metrics, even when the selected ranking metric changes. Each scorecard entry identifies its actual verification domain. Missing scores remain N/A.

Data availabilityUnavailable results show N/A rather than estimated values. Different model coverage can affect comparisons.
02 / DATA AVAILABILITY

Available data

Verification products include 500-hPa geopotential height ACC, RMSE and bias; 850-hPa temperature RMSE and bias; mean sea-level pressure RMSE and bias; 2-m temperature RMSE and bias; 10-m wind vector RMSVE and SPEED_ERR; and 24-hour precipitation ETS at the ≥0.10-inch (2.54-mm) event threshold. Precipitation ETS is recorded as MET GSS and verified at 12 UTC; the other current daily products use 00 UTC. Data availability varies by model, region, date, and forecast lead. Available metrics remain selectable regardless of the current region; selecting a metric available only in CONUS switches the plot to CONUS. Missing model, date, or lead combinations still show N/A.

The Skill vs Forecast Lead percentage-skill and Significance comparisons use the standard matching approach: same valid date, forecast lead, region and metric. The Scorecard separately offers an optional Strict mode requiring the same verification-source identifier. Effective Lead-Time Gain instead uses independently available daily means for each model and baseline, to avoid needlessly truncating forecast-hour coverage; differences in verifying dates and sample counts can influence this descriptive comparison.

03 / MEASURES

Verification metrics

ACCHigher is better

Anomaly Correlation Coefficient

Measures how well forecast anomalies align with verifying anomalies relative to a climatological reference. Displayed for 500-hPa geopotential height in the current dashboard.

RMSELower is better

Root Mean Square Error

Measures overall error magnitude in the variable's physical units (K, m, hPa or m/s). Larger errors receive more weight than small errors because differences are squared.

MECloser to zero

Bias (mean error)

The mean signed forecast-minus-observation difference for scalar fields. Positive and negative values indicate opposite errors; rankings compare absolute distance from zero, while Time Series shows the signed value.

ETSHigher is better

Equitable Threat Score

Measures categorical precipitation event skill while accounting for hits expected by chance. The 24-hour precipitation event threshold is ≥0.10 inch (2.54 mm).

RMSVELower is better

10-m wind vector error

Root mean square of the full forecast-minus-observed wind vector difference. Includes differences in wind magnitude and direction; it is not scalar wind-speed RMSE.

SPEED_ERRCloser to zero

10-m wind vector speed error

The magnitude of the average forecast wind vector minus the magnitude of the average observed wind vector. This is not the difference between average scalar wind speeds and is not conventional mean vector error.

The displayed values are already-computed verification statistics; the dashboard summarizes and compares those statistics rather than calculating them from raw forecasts and observations.

04 / COMPUTATION

Combining daily statistics

For longer periods or the “All forecast leads” option, the dashboard combines available daily verification statistics according to the metric:

MetricHow scores are combinedInterpretation
RMSE, RMSVEsqrt(mean(score²))Accounts for squared error magnitude
ACCtanh(mean(atanh(ACC)))Combines correlation coefficients
ME, SPEED_ERRmean(signed score)Positive and negative errors can offset
ETSmean(ETS)Average of the displayed daily scores

Statistics are combined from the available daily scores. Differences in sample coverage or the number of available records can affect comparisons; interpret small differences with care.

05 / INTERPRETATION

Model ranks, skill, and scorecards

Overall ranking

Home's ranking at left orders the enabled ranking models by the aggregated absolute verification statistic (highest ACC/ETS, lowest RMSE/RMSVE, or Bias/SPEED_ERR closest to zero). With All forecast leads, only (verification date, forecast hour) samples shared by every enabled model enter both the overall ranking and daily rank history; this avoids comparing different model lead ranges. The Forecast-hour availability table lists actual coverage under the selected metric, region and date window. Turning models on or off recalculates the common sample. If there is no common coverage or fewer than two selected models, the chart shows N/A rather than a misleading ranking. For a single selected lead, each model's period mean uses its available dates. This ranking is not the average of daily ranks. The Home scorecard and other Home summaries retain their separate computations and do not use these ranking-model toggles.

Daily rank history

The Home plot ranks enabled models at each individual verification date. 1 = best (top of chart). Under All forecast leads, each date uses only samples present for all selected models at identical forecast hours. Lines show rank changes, not raw score changes; tooltips show the actual aggregated value.

Skill vs Forecast Lead

Each forecast day on the Difference plot compares the model's aggregated metric with a selected baseline (GFS by default), using the fixed Standard approach of matching available valid dates and forecast hours. Positive percentages indicate improvement and negative percentages indicate degradation. The 0.0% reference is always labeled. The difference/skill plot can show EVS-style significance boxes on the same axes when Significance is enabled (on by default). The upper Forecast Hour Mean chart shows the arithmetic average of available daily absolute verification scores at each forecast hour for each selected model, regardless of baseline pairing. Missing data remain gaps, and sample sizes can differ across models. This average is intentionally distinct from RMS/Fisher aggregation used for relative skill.

Effective Lead-Time Gain

This plot estimates the additional forecast hours needed for each model to reach the same fitted verification quality as the baseline at each of its available forecast hours. Positive gains mean the model retains that quality longer. Unlike the Difference and Significance plots, it uses the independently available arithmetic means from Forecast Hour Mean for each model and baseline, even if dates and verification-source labels differ. The curves are fitted to non-increasing quality, then interpolated only between adjacent available model forecast leads; no extrapolation or interpolation across missing lead steps. True equal quality at the same forecast hour appears as 0.0 h. Missing baseline means, missing model means, and targets outside the model's available curve remain unplotted and are explained in the coverage key below the chart. Because the models can use different verification samples, this is a descriptive comparison subject to sample-composition effects, not a statistically significant lead-time improvement.

Effective lead-time gain

The third Skill vs Lead chart compares how far each enabled model could forecast and still achieve the same estimated verification quality as the selected baseline at its forecast hour. For example, +24 h at the baseline F120 means the model reaches the baseline's F120 quality at approximately F144. Negative gains imply less usable lead time. At each forecast hour, pair model/baseline daily verification values by valid date and source mode, average the paired scores, and transform to a quality scale (higher-is-better as-is; lower-is-better negated; Bias/SPEED_ERR use negative absolute distance from zero). Sample-count-weighted monotonic fits remove noisy apparent skill increases before interpolation. Interpolation is limited to neighboring, observed 24-hour forecast steps; there is no extrapolation. The expandable table follows the same diverging color scale as the scorecards: blue for positive hours gained, red for hours lost, and gray at zero. Saturation occurs at ±48 h, consistently across date windows and baseline selections. Where an equivalent forecast hour cannot be established, the table indicates uncolored Before F[hour], Beyond F[hour], Data gap, or No paired data. These conditions never stand for 0 h. Equal fitted quality at the same forecast hour is explicitly recorded as 0.0 h and appears on the zero line. The visible "Why lines start or stop" coverage matrix shows the status at each baseline forecast day, including days where no curve can be drawn. Before/after range refers to the paired data coverage and does not necessarily indicate the forecast model's maximum published lead. Different models may use different date subsets; these are descriptive equivalents, not statistically significant gains.

Scorecard

Home and full Scorecard display percentage improvement relative to the chosen baseline for each metric and forecast lead. Each metric uses the selected region if available; products not available in the selected domain retain their actual region and are labeled as such, without combining domains in a single metric. Baseline cells are 0.0%. Blue indicates positive skill, gray near zero, red negative skill; values are also printed, so color alone is not required.

Time Series

Shows actual metric values for each valid date at a chosen lead, or a metric-specific aggregation across all available leads. It is not baseline-relative. Y-axis units follow the selected metric.

Baseline-relative skill (%)
Higher-is-better: 100 × (model − baseline) / |baseline|Lower-is-better: 100 × (baseline − model) / |baseline|ME or SPEED_ERR: 100 × (|baseline error| − |model error|) / max(|baseline error|, floor)

When the baseline error is close to zero, percentages can become large and should be interpreted cautiously, especially for signed errors. Heatmap color intensity is a visual guide; the printed percentage is the comparison value.

06 / SAMPLING

Dates and forecast leads

The window presets are 7, 15, 30, 60, and 90 days. Each preset ends on the latest available verification date. A Custom Range allows a start and end date within the available 90-day period.

Skill vs Forecast Lead displays Day 0 through Day 15 at whole-day intervals. Effective Lead-Time Gain uses the same baseline, region, metric, window and model selection, but compares independently available forecast-hour means rather than requiring date-matched baseline/model records at every lead. The detailed Scorecard uses a compact subset: Days 1, 3, 5, 7, 10, and 15. Time Series can show a single lead or combine all available leads. Selected dates and forecast leads determine which statistics contribute to each result.

Chart interaction: Hovering over a model name highlights its line on Home, Skill vs Forecast Lead, and Time Series; hovering over a line also identifies its model. Model-selection controls can show or hide traces without altering the underlying scores. Charts support sampling, zooming, panning, resetting the view, and downloading titled PNGs with model legends beneath the charts. Dark and light themes use the same model colors and marker shapes.

07 / UNCERTAINTY

EVS-style paired-difference intervals

The Significance checkbox is enabled by default and adds model-colored, thin EVS-style 95% confidence boxes directly to the lower Difference from [baseline] plot. It does not create a separate chart or change the plotted percentage-skill lines. The boxes are centered on the zero reference, one per model and forecast lead with enough paired daily scores.

Beyond the model's outlined bar

The EVS test flags significance when the mean of raw paired model-minus-baseline values lies outside its zero-centered interval. Because the visible line shows percentage skill, do not use the line's plotted position alone as the formal test. In particular, a significant raw signed Bias difference does not necessarily mean better skill.

Inside the bar

Zero cannot be excluded for that model and forecast lead at the approximate 95% level. Each model has its own bar; there is no shared envelope.

No bar

An interval requires at least 2 matched daily records. Missing model data or dates produce gaps rather than fabricated values. Small samples have unstable uncertainty estimates.

Display and export

Significance is on by default and can be hidden with its checkbox. The thin rectangles follow the metric, models, region, baseline and dates, using standard date/lead pairing; they appear on the same lower interactive plot and its PNG export.

Method: For each model and forecast lead, pair daily scores with the chosen baseline by valid date and lead . The only significance test uses raw daily differences model − baseline, exactly the paired statistic in EVS global deterministic lead-average plotting. Calculate CI half-width = factor × population SD(differences) / sqrt(n − 1), with factor 1.960 for n ≥ 80, 2.000 for n = 40–79, 2.042 for n = 20–39, and 2.228 for n = 2–19. The boxes extend from −CI to +CI around zero. The half-width is divided by the positive matched baseline scale and multiplied by 100 solely to display it on the existing percentage-skill axis; the original EVS significance decision remains in raw units. The former randomization/shared-envelope significance test is no longer used.

Interpretation cautionThe formula follows EVS, but the inputs are daily regional summary scores, not EVS's matched forecast/observation events. These pointwise intervals are not adjusted for serial correlation or multiple comparisons, nor are they confidence intervals for the plotted nonlinear percentage skill. The raw signed difference tests whether the model differs from the baseline, not whether it is better; signed Bias especially requires care.
08 / EXPLORATORY DIAGNOSTICS

Exploratory verification diagnostics

Forecast Lead selection: controls Head-to-Head Win Matrix, Average Advantage vs. Winning Frequency, Model Trade-Off Explorer, Rolling Skill Shifts, Performance Consistency, Paired Block-Bootstrap Uncertainty, Verification Case Finder, Paired Scatterplot, Skill Robustness. Fingerprint, Lead-Time Advantage Envelope, Regional Atlas, Leadership Mosaic, Bias Evolution and Bias–RMSE Portrait always use their available D0–D15 lead sets.

All Skill Explorer comparisons are derived from archived daily regional MET summary scores. They are not member-level, gridpoint-level, event-level, or independent station observations. Standard pairing requires the same UTC verifying date, forecast lead, metric, and region. Distinct verifying-source labels are reported, not silently treated as identical; users should investigate any warnings before interpreting model differences. Missing combinations are N/A, never zeros.

  • Daily Skill Fingerprint: per-date model-to-baseline relative skill using the dashboard's existing metric-direction logic. RMSE and ACC are transformed to percentage improvement relative to that specific day's baseline value; Bias and SPEED_ERR use absolute distance from zero. Color saturates at ±10%, while tooltips show uncapped percentages. Gray means a missing paired daily summary.
  • Lead-Time Advantage Envelope: each lead's daily model–baseline difference is oriented so positive is better. Vertical ranges show 10th–90th percentiles and dots show the median of actual daily native-unit differences; unlike a formal uncertainty band, these display the empirical variation over dates. Unlike Performance Consistency, which focuses on one lead for several models, the envelope shows all leads for one focus model.
  • Average Advantage vs. Winning Frequency: every selected comparison model is paired independently with the chosen baseline; the separate focus-model selection does not substitute another model for any row. Aligned model rows show arithmetic mean of native-unit daily advantages on the left and (wins + half ties)/matched dates on the right. Each model shares dates with the baseline, but different model rows need not use the same dates. Every row shows its matched-day count, and the two independently scaled axes make close values legible without shifting them. This is descriptive, not an all-model matched-date ranking.
  • Adaptive comparison displays: Average Advantage vs. Winning Frequency uses aligned model rows rather than overlapping scatter markers. A descriptive coverage guide (max(3, min(21, half of selected calendar days rounded up))) flags limited samples without suppressing actual models. The Pareto graphic remains visible whenever at least two models have jointly matched data; a single eligible model displays a two-metric skill profile. No-data cases are explicitly described. Missing and zero values are never conflated.
  • Two-Metric Trade-Off / Pareto Frontier: Models with both selected metrics are compared against the same baseline on verification dates common to every retained model, both metrics, the chosen lead and region. If a model has no overlap with the initially selected comparison set, the view can omit that model (explicitly named) instead of hiding the entire valid plot. For each metric, aggregate matched daily values using that metric's existing aggregation (RMS, Fisher-transformed ACC or arithmetic mean); convert to baseline-relative percentage skill. A point is non-dominated if no other plotted point equals or exceeds it on both metrics and is strictly better on at least one. A single non-dominated model is highlighted while retaining every eligible model point; a single eligible model is shown as a two-metric profile. No metric weights or composite scores are assumed. If no common dates exist, the plot is N/A; excluded models and sample counts are disclosed. Verify source differences before interpreting.
  • Paired Block-Bootstrap Uncertainty: exploratory percentile interval for the arithmetic mean *native-unit daily advantage* at a selected lead (not the nonlinear aggregate relative-skill percentage). Resample circular blocks of seven consecutive calendar days 800 times, retaining missing-calendar-day slots and accepting draws only with sufficient matched scores. At least 21 matched verification dates are required; the interval uses 2.5th–97.5th percentiles. The share of positive resamples is descriptive, not a p-value, model probability, or formal significance finding. Block length is a sensitivity choice and does not establish the true temporal dependence. Results may be unstable with seasonal/nonstationary data, source mismatches or missing dates; compare with Leave-One-Week-Out robustness and existing EVS-style intervals.
  • Original MET STAT scope: a November 11 probe examined 20 published files, including CNT:RMSE/ME, VCNT:RMSVE and CTS:GSS summaries. All 8,171 returned SUMMARY records had TOTAL=1: the published percentile fields are not point-level error distributions or verifying sample sizes. Four surface-product URLs were unavailable. A proper Taylor diagram still needs centered correlation and compatible forecast/observation standard deviations; reliability and ensemble rank graphics require appropriate contingency counts or member-level input. No unsupported new statistics or ingestion changes were introduced.
  • Head-to-Head Matrix: pairwise matched dates at one forecast lead. A row model wins when its daily regional score is better in the metric's preferred direction; signed Bias and SPEED_ERR compare absolute magnitude. The displayed win-equivalent rate is (wins + 0.5 × ties) / (wins + losses + ties), not a forecast-event success rate. Each pair can have different dates; n is shown on every populated cell.
  • Regional Atlas: independent date/lead pairing and aggregate statistics within each actual region. Each colored cell is a percentage skill from aggregated *paired* model and baseline scores, not the mean of daily percentages. Regions are not substituted or pooled.
  • Performance Consistency: each observation is a daily matched score difference in native units, oriented so positive is better (for target-zero metrics, improvement in absolute error). Whiskers are the observed minimum and maximum, boxes show Q1–Q3, and the line is the median. The single, column-aligned hover readout displays mean, median, quartiles, range, counts and sample size for each model row; individual dots reveal verification date, both matched metric values, native-unit advantage, and verification-source warnings. They are distributions of daily summary differences, not distributions of point-level forecast errors.
  • Rolling Skill Shifts: each 7- or 15-day trailing window recomputes baseline-relative skill from matched date/lead daily summary scores, requiring at least half of its calendar days to contain pairs. Points are descriptive and highly overlapping, so they do not establish statistical significance or causality.
  • ACC 0.80 Horizon: forecast lead where independently averaged daily H500 ACC first crosses downward through 0.80. Linear interpolation is permitted between consecutive 24-hour leads; missing steps, no crossings, or crossing outside data boundaries are labeled, never extrapolated. Daily samples need not be identical across models, and this is distinct from Effective Lead-Time Gain.

v1.3.0 diagnostic investigations

  • Model Leadership Mosaic: a leader is selected among enabled models available at the same region/metric/date/lead (at least two); models with shorter forecast ranges simply stop participating at later leads. Tooltips list the participating and unavailable models. Ties share fractional first-place credit in the accompanying lead histogram, whose bars can be hovered to see percentages, date counts, and how many models competed. Shares across different leads can reflect different model pools. A differing verifying source is flagged, not assumed equivalent. The number and identity of enabled models are critical for interpreting first-place frequency.
  • Verification Case Finder: orders paired daily focus-model-versus-baseline results by native-unit improvement or deficit, or by absolute day-to-day change in that improvement (only consecutive UTC verification dates). These are daily regional verification-score anomalies, not detected weather events. Clicking a Case Finder row highlights its date across diagnostics; its Time Series button opens the date directly without first selecting it.
  • Paired Scatterplot: plots focus-model score against baseline score for each common date/lead. The 1:1 line means equal raw score; dot colors interpret the metric's higher/lower/target-to-zero direction. Each dot is a daily aggregate, not one gridpoint or individual forecast event.
  • Signed Bias Evolution: shows signed bias for a single model by date/lead. Negative bias is blue, positive bias red; neither means automatically better skill. The symmetric display scale uses the 95th percentile of absolute plotted values, clipping extreme values visually without clipping tooltip values.
  • Bias–RMSE Portrait: only models/dates/leads with both a signed bias and the corresponding RMSE enter a plotted point. Bias is aggregated as a signed mean, RMSE by root-mean-square aggregation of archived daily RMSE values. The x-axis is absolute aggregated mean bias and the y-axis aggregated RMSE; the plotted pair is not a variance decomposition. Lines connect adjacent 24-hour leads only. Each model/lead may use a different date sample.
  • Leave-One-Week-Out Robustness: recomputes matched aggregate baseline-relative skill after removing one calendar week (weeks start Monday). A result requires at least two observed calendar weeks and three paired days remaining. The dashed horizontal line is the full-period skill; each point is the result after omitting its labeled week, and red dots indicate a reversed sign of the advantage. A point far from the line means the comparison is sensitive to that week. Reversal counts are descriptive, not confidence intervals or significance tests.
  • Comparison coverage: the Explorer header shows paired daily dates, share of the selected calendar window, cross-model source mismatches, and unspecified source labels for the focus/baseline pair at the chosen forecast lead. This indicates data coverage, not statistical confidence.

Interpretation: daily scores are temporally correlated; do not treat n daily records as n independent forecast-observation events. The data do not support rank histograms, reliability curves, Taylor diagrams, or precipitation contingency performance diagrams by themselves. See ADVANCED_DATA_REQUIREMENTS.md for exact inputs needed and safe ingestion options.

09 / CAUTIONS

Notable Signals and limitations

Home's Notable Signals compares each model's most recent 15-day period with the preceding 15-day period, using the available headline metrics across forecast leads. It displays up to six of the largest percentage changes. Blue upward arrows indicate improvement; red downward arrows indicate degradation. Stronger shades indicate larger changes, and at least one of each direction is included when both are present.

Signals are an automated way to identify possible changes in recent summary performance. They are not statistical significance tests, forecast alerts, or confirmed changes in model quality. They use fixed 15-day windows rather than the Home ranking chart's selected date range or forecast lead.

  • Small differences in scores do not necessarily imply a meaningful difference in forecast quality.
  • Performance depends on metric, geographic region, forecast lead, verification period, and verifying dataset.
  • Not all models have data for every metric, date, or lead; N/A and gaps represent unavailable information, not zero performance.
  • Combining different forecast leads or comparing models with different coverage can obscure lead-specific differences.
