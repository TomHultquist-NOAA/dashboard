01 / DATASET

Scope & evaluated models

The initial dashboard is a browser-based demonstration for five global guidance systems: GFS, GEFS, AIGFS, AIGEFS, and HGEFS. Its only model group is Global. The available geographic domains are Global, Northern Hemisphere, Southern Hemisphere, and Tropics.

The supplied records cover 90 daily valid dates (July 9–October 6, 2026) and daily forecast leads from Day 0 to Day 15 (0–360 hours, every 24 hours). All numeric statistics, ranks, completeness values, and change signals are synthetic. They are intended to demonstrate behavior, not forecast quality.

Demonstration data onlyThese values have not been produced or certified by OMD EVS. Do not use model ranks, skill scores, or signals from this prototype for scientific or operational conclusions.

03 / MEASURES

Verification metrics

ACCHigher is better

Anomaly Correlation Coefficient

Measures how well forecast anomalies align with verifying anomalies relative to a climatological reference. The current catalog uses ACC for 500-hPa height. The source CSV supplies the ACC score directly.

RMSELower is better

Root Mean Square Error

Measures overall error magnitude in the variable's physical units (K, m, hPa or m/s). Larger errors receive more weight than small errors because differences are squared.

BiasCloser to zero

Mean signed error

Indicates the direction and size of systematic error. Positive and negative values carry different physical meaning; the ranking compares absolute distance from zero, while Time Series retains the signed value.

ETSHigher is better

Equitable Threat Score

Measures categorical precipitation event skill while accounting for hits expected by chance. Used only for 24-hour precipitation in this initial prototype. The CSV carries the already-computed ETS statistic.

The dashboard does not reconstruct forecast–observation pairs, ACC anomalies, or ETS contingency tables from the CSV. Those computations must occur upstream in EVS/METplus. Thresholds and valid time/accumulation details must be documented with real EVS feeds.

04 / COMPUTATION

Combining daily statistics

Each regional CSV contains one precomputed statistic for each available valid date × model × metric × lead. The prototype applies these rules when it combines multiple records for a selected time window or all forecast leads:

MetricCurrent prototype aggregationImportant qualification
RMSEsqrt(mean(RMSE²))Equal weight per available stored score
ACCtanh(mean(atanh(ACC)))Fisher-z approximation for correlations
Biasmean(signed Bias)Positive and negative biases can cancel
ETSmean(ETS)Simple mean, not recomputed from pooled contingency counts

The current code does not weight pooled scores by sample_count or validate matched samples across models. Though the CSV includes sample count and completeness fields, these are not used to reject or reweight records in the prototype’s ranking and skill calculations. This must be revisited before operational deployment.

05 / INTERPRETATION

Model ranks, skill, and scorecards

Overall ranking

Home's ranking at left orders models using the aggregated absolute statistic across the selected dates and forecast lead(s): highest ACC/ETS, lowest RMSE, or Bias closest to zero ranks first. It is not the average of daily ranks.

Daily rank history

The Home plot separately ranks all models with a valid score at each individual date. 1 = best (top of chart); larger rank numbers are lower-performing. The lines show rank changes, not raw score changes.

Skill vs Forecast Lead

Each forecast day compares the model's aggregated metric against the selected model baseline (GFS by default). Positive percentages mean improvement and negative percentages mean degradation relative to that baseline.

Scorecard

Home and full Scorecard both display percentage improvement relative to the chosen baseline for the relevant metric/forecast lead. Baseline cells are 0.0%. Blue indicates positive skill, gray near zero, red negative skill; values are also printed, so color alone is not required.

Time Series

Shows actual metric values for each valid date at a chosen lead, or a metric-specific aggregation across all available leads. It is not baseline-relative. Y-axis units follow the selected metric.

Baseline-relative skill (%)
Higher-is-better: 100 × (model − baseline) / |baseline|Lower-is-better: 100 × (baseline − model) / |baseline|Bias: 100 × (|baseline bias| − |model bias|) / max(|baseline bias|, floor)

For near-zero denominators, the code uses protective floors. Bias uses a metric-specific denominator floor; relative Bias percentages should be interpreted cautiously near zero. The colored heatmap applies an additional nonlinear saturation for presentation only, not to the numeric skill calculation.

06 / SAMPLING

Dates and forecast leads

The window presets are 7, 15, 30, 60, and 90 days. Each preset ends at the newest available verification date in the loaded CSV, not necessarily the current calendar date. A Custom Range may select start and end dates within the 90-day archive. Dates are treated as UTC calendar dates.

Skill vs Forecast Lead uses Day 0 through Day 15 at whole-day intervals, with genuine points present in the synthetic data. The detailed Scorecard uses a compact subset: Days 1, 3, 5, 7, 10, and 15. Time Series can show a single lead or combine all available leads. Dates and leads are filtered before metric aggregation.

07 / CAUTIONS

Notable Signals and limitations

Home's Notable Signals compares each model's most recent 15-day period with its preceding 15-day period, across the prototype's configured headline metrics. Arrows are based on the direction of improvement; green means improved and red means degraded. Signals are changes in summary performance, not statistical significance tests or operational alerts.

  • No confidence intervals, hypothesis tests, or significance thresholds are presently applied.
  • Spatial masks, grid resolution, event thresholds, and common verifying samples are not validated in the browser.
  • Model availability may differ by metric, date, or lead in real EVS output; missing combinations should remain missing rather than be assigned a score.
  • Comparing statistics pooled across leads can obscure systematic lead-dependent behavior.
  • Prototype regions describe pre-generated data partitions; actual geographic masks/weights belong in upstream verification processing.
08 / IMPLEMENTATION

Transitioning to EVS data

EVS is intended to remain the source of computed verification statistics. A server-side normalization process would transform EVS-native daily CSVs into a stable dashboard schema, preserving the forecast model/version, valid time, lead, variable, metric, verification target, region, threshold where relevant, sample count, and data quality metadata.

The prototype currently reads data/regions/*.csv through a browser-side adapter. The exact CSV contract is documented in DATA_FORMAT.md and the implementation approach in ARCHITECTURE.md, both included in this package. The normalization tool is a starting template, not a finished EVS adapter.
